工具与平台选型

一句话：2026 年的平台变化太快，选型的关键不是挑"最强的产品"，而是让每一层都能换。默认推荐 AWS Bedrock + AgentCore；如果贵司已经深度使用微软 365 或 Google Workspace，换成对应的云平台。

#四条实施路线

A 低代码拼装 B 企业平台 C 写代码自研多 Agent D 订阅"AI 员工" + 自建骨架
代表 n8n/Make/Zapier + Dify/Coze + 各类 SaaS Salesforce Agentforce、Microsoft Copilot Studio、HubSpot Breeze LangGraph、Strands、OpenAI Agents SDK、Claude Agent SDK、Google ADK + MCP（跑在云托管服务上） OpenAI Dots、Grok Bot、Claude Cowork 等，加上自建的流程骨架
上线 4–8 周 2–4 个月 3–6 个月 最快
灵活性 中 中偏低 高 员工层低，骨架层高
复杂长流程 弱 中 强 取决于骨架
治理和审计 弱 强 自建，可以做强 员工层弱
平台绑定 中 高 低 高

💡 贵司希望一步到位，所以推荐以 C 为主、跑在云平台的托管服务上，D 只当受控的"员工工位"。

#各类工具的定位

#常驻型 Agent（Dots、Muse、Cowork/Duet、Grok Bot）：只当受控工位

  • 共同问题：没有可以单独控制的知识层；治理和审计偏弱。Gartner 的评价是"自主性跑在了治理前面"。
  • 2026 年的真实事件：Dots 连续处理 10 个任务时 19.7% 出现中度越权，第三方测试发现它会批准自己被标记的动作；Muse 被发现能看到其他用户的信息；Grok Bot 同一账号下所有 bot 共用一台电脑和凭据池，官方文档原话是"不要把不同的 Bot 当作安全边界"。
  • 用法：给 AI 开独立账号和邮箱；银行、支付、域名的双重验证不交给 AI；花钱只用有额度上限的虚拟卡；对外发送、花钱、修改 CRM 关键字段都要审批。
  • 新进展（✅ 11-13 核实）：Claude 的 Compliance API 从 2026-08-26 起覆盖 Cowork 的会话记录（仅 Enterprise 计划），弥补了早期"Cowork 不进审计日志"的缺口。OpenAI 的 Business Premium 席位约每人每月 $125（月付）或 $100（年付），含第一个 dot。

#Paperclip：可以当"AI 公司管理后台"，但要先加固

  • 是什么：开源（MIT）的 Node.js 服务 + React 界面，把一群 AI Agent 组织成一家公司：组织架构、岗位、预算、审批、任务看板、活动日志。11.3 万星，每 1–2 周发一版（最新 v2026.1106.0）。
  • 问题：2026 年共 12 个安全公告（5 个严重级）；默认部署模式不需要登录；Claude 和 Codex 适配器默认跳过权限确认；它的审批只管经过它网关的调用，Agent 自己的命令行和已登录账号不受管。截至 11-13，DNS 重绑定远程执行（GHSA-x8hx-rhr2-9rf7）和 Codex 继承 Gmail 发信（GHSA-gqqj-85qm-8qhf）两个公告仍未标注修复版本（✅ GitHub）。
  • 定位：低风险岗位（调研、内容、内部报告）可以直接用；高风险岗位只能调用受控工具。第一期不作为默认组件，可以做 2–4 周的并行概念验证。

#AWS Quick：人类驾驶舱和后台流程

  • 适合：Owner 的看板、对话式查询、人工审批任务中心、后台流程自动化（开票、对账、催款、合同归档）、内部知识入口。它能直接接自建的 Bedrock 知识库，人和 AI 共用一套知识。
  • 不适合：面向客户的前台、外联、Agent 组织编排。定时或 API 触发的自动化以"服务级身份"运行，网页端没有逐个动作的确认。
  • 费用：1 名用户 Enterprise 档约每月 $290，含 18 个 Agent 小时，超出每小时 $3。

#SageMaker：第一年用不上

新公司没有历史数据。积累 6–12 个月数据后，可以用来做线索评分、流失预测，或把高频任务微调成小模型降成本。

#底座怎么选

贵司现状 推荐底座
没有现成的办公生态（新公司默认） AWS Bedrock + AgentCore：模块最灵活，纯按用量付费，模型选择最多，绑定最低；还能顺带用 AWS Quick
已经在用微软 365 / Teams Microsoft Foundry + Agent 365 + Microsoft Agent Framework
已经在用 Google Workspace Gemini Enterprise Agent Platform + ADK
销售和客服完全建在 Salesforce 上 前台用 Agentforce 360，后台用云平台
在中国大陆运营 阿里云百炼、火山引擎 HiAgent 或腾讯云 ADP，加已备案的模型

为什么默认 AWS（💡）：

  • AgentCore 的 13 项服务在 us-east-1、us-east-2、us-west-2 全部可用 ✅；按用量计费，没有预付和最低消费 ✅。
  • Bedrock 上的模型最多：Anthropic、OpenAI、Meta、Mistral、Qwen、DeepSeek、Amazon Nova 等 ✅。复核者可以用和制作者不同的模型家族。
  • Guardrails、Policy（Cedar）、Registry、Evaluations 这些治理和安全组件是原生的。
  • 但要注意 AgentCorruption：2026 年 10 月 Zenity 披露，一条提示就能接管同账号同区域的所有 AgentCore Agent。AWS 认为这是"已记录的预期行为"，不承认是漏洞；据 Zenity 说，AWS 已把新 Agent 改为 IMDSv2，并收紧了默认执行角色（收紧时间各方说法不一 ⚠️）。本方案用多账号隔离 + 最小权限来应对，见 推荐架构。

#不被平台绑住的四条规则

  1. 四样资产放在自己手里：流程定义（Git 里的状态机）、知识与数据（自己账号里的 S3 和知识库）、规则与权限（Git 里的 Cedar 策略）、评估与日志（自己账号里的审计账本）。
  2. 所有工具都放在 MCP 后面，并锁定协议版本。MCP 在 2026-07-28 发布的稳定版不向下兼容 ✅。
  3. 多模型路由：通过网关调用模型，换模型时只改配置并重跑评估集。
  4. 平台变化是常态：OpenAI Agent Builder 在 2026-11-30 关停，导出时不转换流程图，迁移路径是 Agents SDK 或 ChatGPT Workspace Agents ✅；Coze 企业版 11-30 停售；GPT-6.1 Astra 因安全指标退步被搁置。
