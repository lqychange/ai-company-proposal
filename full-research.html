#1. 项目背景与需求

  • 用户角色：方案方，要为一家新注册的公司做"全公司AI化"设计。
  • 地域假设（💡，需要用户确认）：被AI化的新公司在得克萨斯州注册和运营，客户以美国为主。用户原话是"我们公司在得克萨斯州"，没有说清楚指的是客户公司还是方案方自己。
  • 目标：
    • 把组织架构、责任划分、岗位和业务流程全部AI化。
    • 获客 → 业务对接 → 签合同 → 产出 → 客户跟进，全部由AI自动完成，"中间完全不需要提供任何指令"。
  • 用户最初的五个问题：
    1. 可能吗？
    2. 需要哪些信息或准备？
    3. 需要哪些工具、技术或服务？要横向比较。
    4. 搭建思路和框架（现在不搭建）。
    5. 大概的预算。
  • 后续追问（按时间顺序）：
    1. Dots、Grok Bot、AWS SageMaker怎么样？
    2. 针对这个需求横向对比所有工具，包括第一轮提到的各层工具、Muse、Dots、Claude Cowork、AWS Bedrock，以及类似的横向平台。客户希望一步到位设计和搭建，所以重点是：
      • 未来的可编辑性、定制灵活性和可扩展性
      • 专属RAG、AI治理和安全防护
      • 每个工具能不能做到，怎么做到
    3. 公司在得州，会有什么影响？
    4. Paperclip（github.com/paperclipai/paperclip）这类工具能用吗？还有类似的吗？
    5. AWS Quick能胜任吗？
  • 还不知道、但会明显影响方案的信息：见第12节。

#2. 核心结论（截至2026-11-11）

  1. 可以做，但做不到100%。
    • 一条流程跑成熟后，大约80–95%的工作可以自动完成（💡）。
    • "100%无人"做不到，也不该写进对客户的承诺。在得州，这种说法还可能被当成DTPA（消费者保护法）意义上的误导性宣传，见9.2。
    • 目标应该定为"人只定目标、定红线、处理例外"，类比L4级自动驾驶，而不是L5。
  2. 没有哪个工具能单独一步到位。
    • "一步到位"指的是架构一步到位：每一层都能替换。
    • 客户要牢牢掌握四样东西：流程定义、知识与数据、规则与权限、评估与日志。
    • 2026年平台变化很快，所以这是硬要求。例子：OpenAI Agent Builder 11月30日关停；Coze企业版11月30日停售；MCP协议7月的新版本不向下兼容；GPT-6.1 Astra因为安全指标退步被取消发布。
  3. 推荐底座（💡）：
    • 默认：AWS Bedrock + AgentCore + LangGraph，长周期任务加Temporal。
    • 自建RAG，以MCP服务的形式提供给所有Agent。
    • 治理按NIST AI RMF（AI风险管理框架）来做，安全分层防护。
    • 如果客户已经在用微软365：换成Microsoft Foundry + Agent 365。如果用Google Workspace：换成Gemini Enterprise Agent Platform。
  4. 其他工具的定位（💡）：
    • 常驻型Agent（Dots、Muse、Cowork/Duet、Grok Bot）：只当受控的"员工工位"，不能当公司骨架。
    • Paperclip：可以当"AI公司管理后台"（组织架构、岗位、预算、审批、看板），但要先加固，而且不能让它直接掌控对外的高风险动作。
    • AWS Quick：适合当人类的管理驾驶舱、做后台流程自动化（Quick Automate）、做研究和内部知识入口；不适合当面对客户的前台，也不适合做Agent组织编排。
    • SageMaker：第一年用不上。
  5. 专属RAG、AI治理、安全防护三样都要第一天就建。
  6. 得州的特点是规则少、执法严。
    • 得州AI法（TRAIGA）以"故意"为认定标准，私营B2B公司的负担很轻。
    • 但州总检察长执法积极：2026年10月23日刚依据DTPA起诉OpenAI。DTPA还允许资产不到2,500万美元的企业客户自己起诉。
    • 需要改的设计有四处：销售话术、电话和短信外联、AI语音的同意、按NIST AI RMF做治理（这在TRAIGA下是免责依据）。
  7. 预算（📌）：
    • "一步到位"版：设计和搭建约$15–40万，每月运营约$3,000–20,000。
    • 得州合规另加：一次性约$6k–18k，软件采购多出约5–6.6%的销售税。

#3.2 技术绕不过去的限制

  1. 法律主体：AI不是法人。公司注册、银行开户、实名认证（KYC）、报税都要真人。
  2. 合规：
    • 加州BOT法：在销售场景要说明对方是机器人（📚）。
    • FCC在2024年认定AI语音受TCPA约束（📚）。
    • 中国《人工智能生成合成内容标识办法》自2025-09-01施行（✅）。
    • 欧盟AI法案第50条的透明度义务自2026-08-02起适用（✅）。
    • 得州规定见第9节。
  3. 误差累积：每一步准确率99%，连续50步全对的概率只有约60%（数学推算）。
  4. 提示词注入：客户发来的邮件或文档里可能藏着指令。
  5. 平台规则：LinkedIn禁止自动化操作；邮件服务商会封大量群发的账号（📚）。
  6. 长任务越权（✅）：OpenAI的GPT-6 Astra系统卡显示，一个dot连续处理10个相关任务时，有19.7%会出现中度越权；处理5个任务时是8.6%。

#3.3 哪些业务适合（💡）

  • 适合：标准化、线上交付、中低客单价的业务，比如SEO和内容代运营、数据报告、网站制作、翻译、标准化软件服务、在线培训。
  • 不适合：高价定制咨询、线下或实物交付、强监管行业（医疗、法律、金融）、靠关系维系的大客户销售。

#5.3 常驻型通用Agent（"数字员工"）

OpenAI Dots（未标注的都是✅，来源：TNW、TechTimes、CryptoBriefing、memeburn、BankInfoSecurity，见第13节）

  • 基本情况：
    • 2026-09-29在DevDay发布，底层是GPT-6 Astra。
    • 每个dot有自己的一台云电脑（Linux + Chrome）。
    • 在后台做"主动研究"时，对已连接的应用只能读，不能写。
  • 入口：ChatGPT（含语音通话）、Slack、Teams，以及iMessage/RCS短信。
  • 集成：通过ChatGPT插件连接4,000多个应用。插件可以通过拟议中的"MCP Events"规范触发自动化。
  • 定制：
    • Custom Rules：对每类动作设置允许、禁止或需要审批。
    • "专业dots"（预览）：有独立身份、凭据和系统权限的企业岗位Agent。OpenAI内部试过采购、发票处理、邮件营销、客服、商务合同等岗位。先在企业里试点，并和微软合作接入Agent 365。
    • Business和Enterprise计划可以设团队定时任务。
    • 多个dot协同工作还没开放，OpenAI只说"将来设想由一组dots协作"。
    • Dots专属API或SDK：没找到（⚠️）。开发者拿到的是Agents API里的computer use功能。
  • 知识与记忆：
    • 和用户的ChatGPT账号共享记忆，会从反馈中学习偏好。
    • "ChatGPT Space"是共享区域，队友、ChatGPT和dot在同一份知识上协作；"Pages"是可以共同编辑的文档。
    • 容量上限和RAG控制：⚠️。
  • 治理：
    • Auto-review：在dot的执行环境之外，单独检查关键动作。
    • Activity View：进行中、已排期、已完成工作的实时日志。
    • 凭据隔离：dot能使用保存的密码，但模型看不到密码本身。
    • 改密码和转账永远交给人。

  • 仓库：paperclipai/paperclip，官网paperclip.ing，文档docs.paperclip.ing。

  • 113,143星，18,777个fork，未关闭的issue和PR共6,779个，贡献者261人，已合并2,700多个PR（README）。
  • 用日期作版本号，每1–2周发一版：v2026.1106.0（11/6）、v2026.1023.0、v2026.1012.0、v2026.1005.0、v2026.1001.0、v2026.916.1（9/21）。
  • 只能自己部署，官方托管云版还在排队申请阶段。维护方是"Paperclip团队"，公司和融资情况：⚠️。

定位

  • 官方说法："如果OpenClaw是员工，Paperclip就是公司。"
  • 它是一个Node.js服务加React界面，把一群AI Agent组织成一家公司来运营。本身不是Agent框架。
  • 能接的Agent：OpenClaw、Claude Code、Codex、Cursor（含Cloud）、Gemini CLI、OpenCode、Pi、Hermes（含Gateway）、Grok Build、Kimi Code，以及自定义进程、HTTP接口、外部适配器插件。官方原话："能接收心跳信号的，就能被雇用。"

功能

  • 四个支柱：
    • Agent任务管理：任务、审批和评审关卡。
    • Agent组织架构：人和Agent混编，有角色、权限和边界。
    • Agent员工培训：技能工作室、评估、绩效评审、技能版本。
    • Agent操作系统。
  • 具体功能：
    • 组织架构：上下级、头衔、岗位说明、每个Agent的预算。
    • 目标对齐：任务上挂到项目和公司目标，Agent能看到"为什么要做"。
    • 心跳：按分配的任务、跟进消息或定时自动唤醒，任务沿组织架构上下委派。
    • 预算：公司、Agent、项目三级预算，有阈值提醒和硬停止。注意：按已记录的花费执行，用量上报有延迟或任务还在运行时，可能停得晚一点。
    • 多组织：一套部署可以放多个公司。
    • 任务线程：对话、计划、阻塞项、文件和运行历史都挂在任务上。
    • 治理：评审和审批关卡，批准雇用新Agent，随时暂停、改派或停止。
    • 应用连接：GitHub、Notion、Railway，或者自己的MCP服务器。每个动作可以设为"允许 / 先问 / 关闭"。
    • 技能库和技能工作室：用保存的输入测试，可以恢复旧版本。
    • 定时任务：支持cron、webhook和API触发。
    • 产出物和评论、现成的团队模板。
    • 实验功能：Agent Chat，以及Slack、Discord、Telegram、AgentMail等聊天和邮件连接。
  • 底层能力：
    • 两种部署模式（下面单独说），人员角色，Agent API密钥，短期有效的运行令牌（JWT）。
    • 任务原子领取加执行锁，避免两个Agent抢同一个任务。
    • 基于数据库的唤醒队列。
    • 隔离的执行工作区（git worktree），沙箱提供商有e2b、Cloudflare、Daytona、Modal、Novita、boxd、自建Kubernetes。
    • 插件运行在独立进程里，按能力授权。
    • 密钥加密存储，可以按Agent分配。
    • 关键操作写入持久的活动日志，可审计。
    • 组织可以整体导出和导入，会去掉密钥值；但普通环境变量和本地路径可能还在，分享前要检查。
    • 可选接入OpenTelemetry追踪和Sentry。
  • 审批类型：雇用Agent、CEO战略、预算超支、董事会审批。CEO的战略被批准之前，任务不能进入"进行中"。
  • 工具权限的四道检查（只适用于"应用工具"类连接）：凭据 → 凭据归属（个人、组织或专属某个Agent）→ 哪些Agent能用 → 具体动作是允许、先问还是关闭。
    • 消息渠道（Slack、Discord、Telegram、Teams、iMessage、AgentMail等）没有按动作的开关。
    • 如果允许未关联的外部人员发消息，这些人会被当作受限访客，他们的任务只在隔离工作区和沙箱里运行。
  • 部署模式：
    • local_trusted：默认模式，不需要登录。
    • authenticated + private：需要登录（用Better Auth），适合Tailscale、VPN、局域网。
    • authenticated + public：面向公网。
  • 路线图：
    • 进行中：记忆和知识功能、Agent Chat、云部署。
    • 计划中：MAXIMIZER MODE、工作队列、自组织、组织自动学习、桌面应用、接入外部工单系统（Asana、Linear、Jira）。
  • 遥测：默认开启。关闭方法：设置 PAPERCLIP_TELEMETRY_DISABLED=1 或 DO_NOT_TRACK=1，或者在配置里把 telemetry.enabled 设为false。

#5.8 AWS Quick（✅ AWS官网和文档，2026-11-11）

是什么

  • 由Amazon QuickSight演变而来，原QuickSight的API、SDK和集成继续可用。2025年推出时叫"Quick Suite"，现在叫"AWS Quick"。
  • 组成部分：
    • 聊天Agent：系统自带的"My assistant"，用户也可以自建Agent。
    • Spaces：团队共享资料、看板、数据集、知识库和外部连接的空间。
    • Quick Flows：个人和团队的无代码自动化。
    • Quick Automate：企业级流程自动化。
    • 知识库（Quick Index）。
    • Quick Research：带引用的深度研究报告。
    • Quick Sight：数据看板。
    • Apps：用自然语言生成内部Web应用。
    • 桌面版：能读本地文件、邮件和日历，可以接MCP。
  • 知识库的数据源：S3、SharePoint、OneDrive、Confluence、Google Drive、网页抓取，还能直接接自建的Amazon Bedrock知识库。
  • 接外部系统：OpenAPI、MCP、REST API、Zapier；能嵌入Chrome、Slack、Teams和Microsoft 365。

Quick Automate

  • 只在通过AWS控制台开通的账户里可用，Free和Plus用不了；价格上要Enterprise档。
  • 用自然语言或上传流程文档生成计划，再用可视化设计器调整。支持条件和循环、案例管理、异常处理、自定义代码。
  • 两类Agent：
    • UI Agent：自己操作网页。
    • 自定义Agent：能调用工具和代码，也能发起人工审批任务。
  • 版本管理：只有提交过的版本才能部署；保留变更历史；可以导出导入；开发、测试、生产环境可以用不同的运行配置。
  • 凭据（网站登录、各类集成）加密存储，自动化的作者和使用者都看不到。
  • 触发方式：
    • 定时：在设定时间后15分钟内启动，支持cron表达式。
    • API：StartAutomationJob / DescribeAutomationJob，属于quicksight命名空间。
  • 并发上限：每个触发器最多同时跑10个，每个账户最多50个，可以找AWS申请提高。
  • 自动化目前只能用"Actions"标签页下的集成。
  • 官网案例：Jabil用Automate做应收催收和报价提交，报价更准，废料减少10%，每年节省约40万美元。

治理和安全

  • 统一登录（IAM Identity Center/SSO）、角色权限、自定义权限模板。

#6. 专属RAG（知识层）

为什么必须做（💡）

  1. 它是公司的"大脑"。 产品、价格、条款手册、SOP、案例、品牌语气、客户历史，每个Agent的每个决定都依赖它。
  2. 能迁移。 知识锁在某个Agent产品里，换平台就等于"失忆"。
  3. 能隔离权限。 销售Agent看不到财务明细；A客户的资料不会出现在B客户的方案里。
  4. 能追责。 每个回答都带出处，出了错能查到是哪份文档导致的。

四个组成部分

组成 存什么 怎么做
文档知识 产品资料、SOP、合同模板、案例 关键词加语义的混合检索。可以用Bedrock知识库、Foundry IQ、Google原地索引，或者自己部署pgvector、Pinecone、Qdrant
业务数据 CRM、订单、发票 不放进知识库，通过MCP或API实时查询，避免拿到过期数据
关系知识 客户、联系人、合同、项目之间的关系 知识图谱检索（GraphRAG）：微软GraphRAG v3.3.0（MIT）、Neo4j、Zep的Graphiti v0.31.2
Agent记忆 和每个客户的互动、偏好、历次决定 AgentCore Memory、Mem0 v2.2.1（Apache-2.0，约6.9万星）、Zep、Letta 0.16.8

设计要点（💡）

  • 原始文档和索引都放在客户自己的云账号里。
  • 以MCP服务的形式提供给所有Agent，换Agent时不用重建。
  • 在AWS上，Bedrock知识库可以同时给AgentCore上的Agent和AWS Quick里的员工用，人和Agent共用一套知识。
  • 检索时按Agent角色和客户做权限过滤。
  • 改知识库要走审批、留版本，防止"记忆投毒"（OWASP列出的Agent风险之一）。
  • 每次检索都带出处、留日志，定期评估检索准确率。

#9.1 TRAIGA（得州负责任AI治理法，HB 149，2026-01-01生效）

  • 适用对象：在得州推广、做广告或开展业务的人；产品或服务被得州居民使用的人；在得州开发或部署AI系统的人。
  • "消费者"：得州居民以个人或家庭身份行事时才算，不包括在商业或雇佣场景中的个人。
  • 告知义务：只有政府机构和医疗服务必须告知对方在和AI打交道（§552.051）。私营的非医疗公司没有这项义务。
  • 对私营公司的禁止事项（都以"故意"为标准）：
    • 故意诱导自残、伤害他人或犯罪（§552.052）。
    • 唯一意图是侵犯宪法权利（§552.055）。
    • 故意违法歧视受保护群体，只是结果不均衡不足以证明故意（§552.056）。
    • 涉及未成年人的性内容和深度伪造（§552.057）。
    • 社会评分和生物识别那两条只针对政府。
  • 执法：
    • 只有州总检察长能执法，个人不能依这部法起诉。
    • 总检察长官网设有投诉入口。收到投诉后可以发"民事调查要求"，要求提供8类材料：①用途、使用场景和好处 ②训练或编程用的数据类型 ③输入数据类别 ④输出 ⑤评估指标 ⑥已知局限 ⑦上线后的监控和用户保护措施 ⑧其他相关文件。
  • 整改：收到书面通知后有60天整改期。期满前完成整改，并提交书面说明、证明材料和内部制度的修改，就不会被起诉。
  • 罚款：可整改的每次$10,000–12,000；不可整改的每次$80,000–200,000；持续违规每天$2,000–40,000。
  • 免责和抗辩：
    • 法律推定公司已经尽到合理注意义务。
    • 别人滥用你的AI系统，你不担责。
    • 以下方式自己发现的违规可以免责：外部反馈；对抗性测试或红队测试；按州机构的指引；在实质遵循NIST AI RMF生成式AI配置文件（或其他公认的AI风险管理框架）的前提下，通过内部审查发现。
    • 还没上线的AI系统不罚款。
  • 另外：有执照的人被认定违规后，发证机构还可以吊销执照，并加罚最高$100,000。
  • 监管沙盒（第553章）：
    • 由州信息资源部（DIR）主办，最长36个月，可以有正当理由延期。
    • 测试期间可以免除部分州的执照要求，但上面那些禁止事项不能免。
    • 申请要提交：系统描述、对消费者、隐私和公共安全的影响评估、风险缓解计划、符合联邦AI法规的证明。
    • 目前是否已开放申请：截至2026-11-13仍没找到DIR公开的申请入口，也没查到依TRAIGA提起的执法案例（Chambers 2026实务指南）（⚠️ 请律师确认）。总检察长官网已有TRAIGA的投诉页面（consumer-ai-rights）。
  • 对隐私法的修改：数据处理方要协助控制方保护AI系统处理的个人数据。
  • 对生物识别法的修改：
    • 网上公开的照片或录音，不等于本人同意，除非是本人自己公开的。
    • 用于训练AI的生物识别数据可以豁免，除非系统用来识别特定的人。

#9.2 DTPA（得州消费者保护法，针对欺骗性商业行为）

  • 企业客户也能起诉：资产不到2,500万美元的企业也算"消费者"（§17.45(4)）。
  • 不适用的情况（§17.49）：
    • 书面合同金额超过$10万，且对方有自己独立的律师，不涉及住宅（§17.49(f)）。
    • 交易金额超过$50万（§17.49(g)）。
    • 专业服务里"建议、判断、意见"本身不适用，但对事实的明确虚假陈述、违反明示担保等仍然适用（§17.49(c)）。
  • 执法案例：州总检察长在2026年10月23日依据DTPA起诉OpenAI和Sam Altman，理由是把ChatGPT宣传成"安全可靠"，却没有充分披露它可能输出不准确或有害信息的风险，还涉及对未成年人的伤害。
  • 💡 设计上的影响：
    • 建一份预先批准的话术清单，营销和销售Agent只能说清单上的内容。
    • 安全护栏拦截"保证""100%""完全无人工"这类说法。
    • 方案和合同里写明AI的局限。
    • 所有对话存档。
    • 对外不要宣传"100%由AI完成"，除非能拿出证据。

#9.3 电话和短信推销

  • 要登记（§302.101）：从得州打出、或打给得州买家的推销电话，要先在州务卿处登记，每个营业地点单独登记。登记费$200（§302.106），另交$10,000保证金，可以是担保债券、信用证或存单（§302.107）。
  • "买家"包括企业（§302.001，"人"包括公司）。
  • 豁免很窄：
    • B2B只有买方买来转售或用于生产时才豁免（§302.056）。
    • 向老客户推销，要用同一个名称经营满2年才豁免（§302.058）。新公司用不上。
    • 其他豁免（§302.053、.059、.061等）是否适用，要律师判断（⚠️）。
  • SB 140（2025-09-01生效）：
    • 把"电话推销"扩大到"电话或其他传输，包括文字、图形消息或图片的传输"，也就是短信和彩信都算。
    • 违反第304章（电话营销和州免打扰名单）和第305章的行为，都算DTPA违规，个人可以起诉。
    • 原文里"其他传输"是否涵盖电子邮件，存在解释空间（⚠️请律师确认）。
  • TCPA在得州的诉讼（§305.053）：收到违反联邦TCPA的通讯的人，可以在得州法院起诉，每次违规$500或实际损失；故意违规最高$1,500或实际损失的3倍。
  • 联邦：FCC在2024年认定AI生成的语音属于"人工语音"，给手机打推销电话要事先拿到书面同意（📚）。2026年FCC正在审议一项放宽政治类AI自动电话的请愿（✅新闻）。
  • 💡 设计上的影响：
    • 不做AI陌生外呼；语音Agent只接客户打进来的电话，或做对方预约、同意过的回访。
    • 要么去登记，要么初期只用邮件外联。
    • 外呼和发短信之前，系统自动检查同意记录和免打扰名单。

#9.4 生物识别法（CUBI，§503.001）

  • 声纹属于生物识别信息。为商业目的采集前，必须先告知并取得同意。
  • 不得出售或披露（有少数例外）；要妥善保存；用途结束后1年内销毁。
  • 每次违规最高罚$25,000，由州总检察长起诉。
  • 💡 设计上的影响：
    • 克隆任何人的声音（包括创始人自己）都签书面同意书。
    • 不用声纹来验证来电者身份。
    • 通话开头说明"本通话录音，我是AI助理"：得州只需一方同意即可录音（📚），但打到外州可能需要双方同意。

#9.5 隐私法（TDPSA，2024-07-01生效）

  • 符合联邦小企业管理局（SBA）小企业标准的公司基本豁免；唯一例外是出售敏感数据前要先取得同意。
  • "消费者"不包括在商业场景中的个人，所以B2B联系人数据大多不在范围内。
  • 超出小企业标准后要做的事：隐私声明；45天内响应消费者请求；允许退出定向广告、数据出售和重大决定中的画像；数据保护评估；和数据处理方签合同。
  • 💡 既然要一步到位，现在就把个人数据清单、删除和导出、退出入口建好，并和所有AI供应商签数据处理协议。

#9.6 数据经纪商（第509章）

  • 数据经纪商要在州务卿处登记，每年$300（§509.005）。
  • 💡 采购线索数据前，先确认供应商已登记；在知识库里记录每条数据的来源。

#9.7 电子交易法（UETA，第322章）

  • §322.014(b)：由电子代理之间的互动可以订立合同，即使没有任何人知道或看过。 电子代理和个人之间也可以订立合同（§322.014(c)）。
  • §322.010(c)：在和个人的自动交易中，如果电子代理没有提供防止或纠正错误的机会，个人可以撤销因自己的错误产生的电子记录；这一点不能在合同里约定排除（§322.010(e)）。
  • 💡 设计上的影响：
    • AI答应的条件公司必须履行，所以授权矩阵和规则网关是法律上的需要。
    • 签约流程里必须有确认和更正的步骤。

#9.8 税

  • 特许税（州审计长官网）：
    • 2026–2027年度，收入不超过$2,650,000的不用交税，但每年仍要提交信息报告或股东信息报告。
    • 税率：零售和批发业0.375%，其他行业0.75%，按应税利润计算。收入不超过2,000万美元可以用简易算法，税率0.331%。
    • 薪酬扣除上限$480,000。
    • 每年5月15日前申报（📚）。
  • 销售税（税法§151.351）：
    • 信息服务和数据处理服务有20%免税，也就是按价格的80%征税。州税率6.25%，地方税最多再加2%（📚），实际约5%–6.6%。
    • SaaS一般被当作数据处理服务（📚）。
    • 两个影响：买SaaS、云服务和API大多要多付这笔税；如果你们卖的是SaaS、数据报告这类服务，向得州客户销售时要代收销售税。
    • 财务Agent接入Stripe Tax或Avalara，具体由会计确认。

#10. 初步方案 v0.1（💡，等第12节的问题有了答案后再迭代）

#10.1 设计原则

核心原则："流程为骨，AI为肉"

  • 主干流程用规则写死的状态机：线索 → 商机 → 报价 → 合同 → 收款 → 交付 → 回访。
  • AI只在需要判断的地方介入：写邮件、判断意向、出方案、检查交付物。
  • 每个动作都留日志，能回放，能回滚。

八条原则

  1. 按风险分级：低风险直接执行；中风险由一个AI做、另一个AI审；高风险由人批准。
  2. 逐步放权：依次经过四个阶段——AI做但不发出、人对比结果 → 人一键批准 → 自动执行加抽查 → 只处理例外。每一步放权都用数据决定。
  3. 只有一个数据源：CRM是客户数据的唯一来源，AI之间不靠互相"传话"。
  4. 长周期任务单独保存状态：跟进、续约这类跨周跨月的任务，用Temporal或LangGraph保存状态，不依赖AI的对话记忆。
  5. 最小权限：外部来的内容一律当作不可信。付款、改价、签约这类工具单独隔离，并设额度上限。
  6. 用测试说话：改提示词或换模型之前，先把测试集跑一遍。
  7. 成本熔断：每个任务、每天都设token和预算上限。
  8. 人工控制台：目标是人每天花不到1小时处理例外。

#10.5 可编辑性和可扩展性

谁能改什么（三层）

  1. 业务人员：知识库文档、话术模板、授权金额和折扣上限、审批规则。在管理后台改，有版本、要审批，批完马上生效。
  2. AI运营负责人：每个Agent的岗位说明（提示词）、工具权限、测试集。改完先跑测试，通过了再发布。
  3. 工程师：流程骨架、系统对接、新增Agent。走代码和自动化发布流程。

怎么扩展

  • 新增业务线：复制一套Agent模板，加一块新的知识库分区。Paperclip的组织导出导入可以当模板用。
  • 新增Agent：在登记表里登记，分配身份和规则。
  • 新增工具：做成MCP服务器，接到网关上。
  • 换模型或升级模型：在网关里切换，用测试集复测。
  • 业务量增长：托管的运行环境会自动扩容。注意Quick Automate有并发上限。

#1. AWS: Bedrock, AgentCore, AWS Quick
  • What it is: Bedrock provides the models, Knowledge Bases and Guardrails. AgentCore is the infrastructure for running agents in production. AWS Quick is the workspace for employees.
  • Models on Bedrock: AI21 Labs, Anthropic, Cohere, DeepSeek, Luma AI, Meta, Mistral AI, OpenAI, Qwen, Stability AI, TwelveLabs, Writer and Amazon (Nova). https://aws.amazon.com/bedrock/model-choice/
    • Gemini is not on Bedrock. AgentCore Harness can still call it, along with OpenAI and any OpenAI-compatible provider. https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html
    • It's unclear whether OpenAI on Bedrock covers its proprietary GPT‑6 models or only the open-weight gpt-oss models [unverified].
  • AgentCore services (13): Harness, Runtime, Memory, Gateway, Identity, Code Interpreter, Browser, Observability, Payments, Evaluations, Optimization, Policy, Registry (same docs page).
  • Customization:
    • Works with any framework: LangChain/LangGraph, CrewAI, LlamaIndex, Google ADK, OpenAI Agents SDK, Claude Agent SDK, Strands, or your own. https://aws.amazon.com/bedrock/agentcore/
    • Runtime supports MCP and A2A.
    • Gateway turns your APIs and Lambda functions into MCP tools and connects to existing MCP servers.
    • Harness is a managed agent loop. Each session runs in an isolated microVM, and you can bring your own container.
  • RAG/knowledge:
    • Gateway can reach a knowledge base, MCP servers, internal APIs and Lambda in a single agent turn.
    • AgentCore Memory covers short-term and long-term memory, and memory stores can be shared across agents.
    • I didn't re-check Bedrock Knowledge Bases in this session (managed ingestion/chunking, multiple vector stores, GraphRAG, natural-language-to-SQL over structured data) [unverified for 2026].
  • Governance:
    • Registry: a catalog of agents, MCP servers, tools and skills with a publish → review → approve workflow. It covers resources on AWS, on-premises or other clouds.
    • Policy: deterministic rules written in natural language or in "Dogwood", a policy language compatible with Cedar. Gateway enforces them on every tool call.
    • Evaluations: works on OpenTelemetry/OpenInference traces.
    • Optimization: AI-generated recommendations, versioned configurations, and A/B tests by splitting traffic through Gateway.
    • Observability: OpenTelemetry data sent to CloudWatch.
  • Security:
    • Guardrails has six safeguard policies: content/word filters, prompt-attack detection, denied topics, PII redaction, and hallucination detection (contextual grounding plus Automated Reasoning checks).
    • Automated Reasoning checks use formal logic, and AWS claims up to 99% accuracy. Protections now also cover code: malicious code injection and PII inside code.
    • ApplyGuardrail API works with any model, including OpenAI, Gemini and self-hosted ones.
    • Cross-account guardrails can be enforced across a whole AWS organization. https://aws.amazon.com/bedrock/guardrails/
    • Agent identity works with Cognito, Okta, Entra ID and Auth0.
    • AWS says access policies are "verified by automated reasoning".
    • Private networking (VPC/PrivateLink) [unverified this session].
  • Scalability: serverless Runtime, isolated sessions, long-running async agents, and multi-region deployment "from day one".
  • Lock-in: low for frameworks and models; AWS explicitly says you can change your mind later "without rewriting infrastructure". Lock-in is higher for IAM, Dogwood/Cedar policies and CloudWatch.
  • Pricing:
    • Bedrock is pay-per-use with no upfront cost or minimum.
    • AgentCore is billed by consumption per service, with no upfront cost or minimum fee.
    • AWS Quick pricing [unverified].
  • Notable 2026 changes:
    • AgentCore Payments: agents can pay for APIs and MCP servers using the x402 protocol and the Machine Payments Protocol, with Coinbase CDP and Stripe (Privy) wallets and spending limits.
    • Harness, Optimization, Registry and the Dogwood policy language are new.
    • Quick Suite is now "AWS Quick". It turns chat into documents, decks and dashboards, runs research, builds no-code apps, and connects to Salesforce, HubSpot, ServiceNow and Slack. https://aws.amazon.com/quick/
#2. Microsoft: Foundry, Copilot Studio, Agent 365
  • What it is: Microsoft Foundry (the docs path has moved from /ai-foundry/ to /foundry/) includes Agent Service, the model catalog and Foundry IQ. Agent 365 is the control plane for governing agents. Entra, Purview and Defender provide identity, data protection and threat protection.
  • Customization: Agent Service offers four ways to build, from configuration-only to full code. https://learn.microsoft.com/en-us/azure/foundry/agents/overview (page dated 2026‑10‑26)
    • Prompt agents: configured in the portal, SDK/REST or azd, so they fit CI/CD.
    • Voice prompt agents: use Voice Live.
    • Hosted agents: your own code and framework in a container, with a managed endpoint, scaling and identity.
    • Responses API: for agents you already run elsewhere.
    • Microsoft Copilot harness (preview): optional, for multi-step tool and skill workflows.
    • Toolboxes: curated tools (web search, file search, code interpreter, MCP servers, custom functions) shared through one managed MCP endpoint with central authentication, governance and versioning.
    • Model swaps: you can change models without changing agent code. The docs give GPT‑4o, Llama and DeepSeek as examples.
    • Claude models in Foundry and A2A support [unverified this session].
  • RAG — Foundry IQ: a managed knowledge layer built on Azure AI Search. https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/what-is-foundry-iq
    • One knowledge base can serve multiple agents.
    • Sources: Blob storage, SharePoint, OneLake and the web.
    • Chunking and embeddings are automatic. Search can be keyword, vector or hybrid.
    • "Agentic retrieval" uses an LLM to plan queries, runs subqueries in parallel, reranks results and returns citations.
    • Permissions: access lists are synced, Purview sensitivity labels are honoured, and queries run under the caller's Entra identity.
    • It can be used from Copilot Studio, Microsoft Agent Framework or REST.
    • Some features are GA and others are still in preview.

    • Microsoft 365 admins: agent inventory, IT-controlled onboarding, security policy templates, analytics.
    • Entra admins: agent identities and access.
    • Purview admins: data governance.
    • Defender admins: security posture and threat protection.
    • Inventory: any agent with an Entra Agent ID published through Microsoft 365 channels appears in the inventory automatically. Agents built elsewhere need extra steps.

EU AI Act

#What this means for the architecture

Three signals support code-first, portable orchestration with protocols pinned to known versions. Hosted builders are being withdrawn (OpenAI Agent Builder, Coze Enterprise). The MCP revision breaks older implementations. Agent identity and audit now have NIST and Microsoft reference models.

On regulation, the lead-gen and marketing agents fall outside Colorado's definition of covered automated decision-making. Contract or credit-like decisions could fall inside the 2027 Colorado and California regimes. EU Article 50 disclosure duties already apply to client-facing agents.
