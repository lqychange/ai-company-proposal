AI 治理

一句话：按 NIST AI RMF 搭框架、按"三道防线"分工、把规则写成代码放进 Git。一个人做不了传统的"职责分离"，就用机器、时间、不可篡改的记录和外部第三方来代替"第二个人"。

#框架：NIST AI RMF + 三道防线

NIST AI RMF 职能 本方案里的机制
治理（Govern） 公司宪章；三道防线；Owner 职责；治理即代码；变更流程；人物登记
映射（Map） 用例和风险台账：每个人物、每类动作的 R 等级，以及适用的法规
度量（Measure） 离线和在线评估；RAG 指标；复核官校准；红队测试
管理（Manage） 自主度的晋升和降级；熔断；事件响应；事后复盘
  • 这张对照表本身就是合规材料：在得州 TRAIGA 下，实质遵循 NIST AI RMF 并通过内部审查发现的违规可以免责。
  • NIST AI RMF 目前仍是 1.0 + 生成式 AI 配置文件（AI 600-1），没有 2.0；NIST 正在做 Agent 标准倡议和面向 Agent 的控制叠加，出来后再对齐 ✅。
  • ISO/IEC 42001：贵司要不要做这项认证，第二年按客户要求再定。

#治理即代码

governance/                  # 一个 Git 仓库
  constitution.md            # 公司宪章：红线、诚实、AI 身份告知
  thresholds.yaml            # 阈值唯一来源 → 生成 Cedar 常量、风险引擎配置、K3 文档
  personas/<id>.yaml         # 人物卡
  policies/*.cedar           # 授权策略，附带测试用例
  guardrails/*.json          # 护栏配置（组织基线 + 岗位）
  prompts/                   # 宪章以外的提示词模板
  evals/<persona>/           # 评估集：标准题、对抗题、合规题
  knowledge/manifest.yaml    # 知识域、分级、访问表
  processes/*.asl.json       # 状态机定义
  risk-register.yaml         # 风险与合规台账
  adr/                       # 架构决策记录

这个仓库同时也是 TRAIGA 调查时要提供的 8 类材料的来源。

#变更分四类

类别 例子 流程
收紧 降低额度、增加屏蔽话题、停用工具 自动检查通过就发布，事后通知 Owner
中性 FAQ 措辞、非规则类知识 自动检查 + 复核官AI + 抽查
放宽 提高额度、增加工具、新增人物、晋升自主度、换模型 合规官AI写风险说明 → 预发环境跑评估 → Owner 批准 → 等 24 小时冷静期 → 灰度发布 → 全量
紧急 事件处理中的临时变更 破窗：Owner 用硬件密钥执行，72 小时内补复盘

#一个人怎么做职责分离

  1. 机器当第二把钥匙：复核官和合规官在别的账号、用别的模型家族。
  2. 时间当第二把钥匙：放宽类变更有冷静期。即使 Owner 被钓鱼或一时冲动，也有 24 小时可以反悔。
  3. 记录不可篡改：Owner 自己的操作也写进审计账本，删不掉。
  4. 外部第三方：律师和 CPA 每季度或每年复看一次。

另外，Owner 日常登录的身份只有"审批人"和"只读"权限，没有云平台管理员权限；基础设施只能通过流水线修改。

#评估体系

类型 内容 什么时候跑
离线评估 每个人物三类题：标准题、对抗题（注入、诱导越权）、合规题（话术、AI 身份告知） 每次改提示词、模型、工具或知识；每周全量
在线评估 对生产数据按比例抽样打分 持续；灰度端点 100% 打分
质量金丝雀 每小时用生产配置跑几道标准题 持续；分数下降自动降级
红队 自动化红队工具在预发环境跑 每月；每季度可以请外部做一次
业务 KPI 自动化率、例外率、审批时延、复核分歧率、客户满意度、每单成本 每周报告

评估集需要贵司参与：标准题的"正确答案"来自贵司的业务判断。请在前期准备里提供 真实或模拟的客户对话和刁钻案例。

#模型和成本治理

  • 模型白名单，锁定版本；换模型属于"放宽"类变更：跑完评估集 → 灰度 10% 运行一周 → 全量。
  • 数据保留模式是选模型的硬条件：处理客户机密数据的人物，只用允许零数据保留的模型。
  • 成本四层控制：单次调用的 token 和工具次数上限 → 每个人物的日预算 → 按人物归因的成本报表 → 账号预算用到 120% 自动挂拒绝策略。

#对外透明

  • AI 身份告知：人物可以有名字（如"Ava，X 公司的 AI 助理"），但第一次接触时和邮件签名里都必须说明自己是 AI，并且随时可以转给真人。不使用真人的名字和照片。
  • 已批准宣传用语库：所有对外的能力、效果和价格说法都必须出自这个库，复核官逐条核对。这是防 DTPA 误导性宣传的主要手段。
  • 外联合规：真实发件人、退订链接、及时处理退订；退订名单是规则里的一个条件，命中就拒绝发送。

#事件与熔断

级别 名称 作用 谁能触发
K1 停工具 某个工具对所有人停用 Owner、哨兵AI
K2 停人物 某个人物停职 Owner、哨兵AI
K3 停渠道 停止对外发信或发布 Owner、哨兵AI
K4 安全模式 所有对外动作都要 Owner 批准 Owner、哨兵AI、缺席检测
K5 全停 所有人物停止 只有 Owner；预算动作

自动触发只能收紧，不能放宽；恢复一律由 Owner 操作。哨兵AI每小时最多触发 3 次，每次都通知 Owner，K5 不归它管。每次事件都要复盘，产出新的评估用例、规则变更和知识修订。
